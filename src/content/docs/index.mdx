kubetower is one Go binary that serves its own interface. You run it, you open a
browser, it talks to the clusters already in your kubeconfig.

## What you need

- **A kubeconfig** — the same file `kubectl` reads. `KUBECONFIG` is treated as a
  list and merged the way `kubectl` merges it.
- **A browser.**

Nothing else. No runtime to install on the host, no database, no agent in the
cluster, no account.

## Pick where it runs

| | Where | Good for | Page |
| --- | --- | --- | --- |
| **On your machine** | a binary on your laptop, listening on loopback | one operator, several clusters, air-gapped workstations | [Install](/docs/install) |
| **In a container** | the same binary in an image, kubeconfig mounted | not installing anything on the host | [Run in a container](/docs/container) |
| **In a cluster** | one console a team shares, behind your ingress | central access, single sign-on | [Deploy with Helm](/docs/helm) |

## There is no release yet

Measured on this repository: `git tag` and `gh release list -R thonicdev/kubetower`
both return nothing. Until the first tag, the way in is to build it.

<CommandRow command={null} placeholder="Binaries: available at v0" />

```bash
git clone https://github.com/thonicdev/kubetower
cd kubetower

# The interface, compiled into the binary.
cd web && pnpm install --frozen-lockfile && pnpm run build && cd ..

# The binary.
go build -trimpath -o kubetower ./cmd/kubetower
```

Go at the version [`go.mod`](https://github.com/thonicdev/kubetower/blob/main/go.mod)
pins, and Node 22 with pnpm for the interface. If you only touch the backend you
can skip the first command — the binary then serves a page telling you the
interface is not built rather than failing to compile.

## The first run

```bash
./kubetower
```

There is **no way to start it without a password**, and that is not a setting: the
process holds administrator credentials for production clusters. On a first run it
draws a 20-character one, shows it **once**, and keeps only its bcrypt hash.

It is shown three ways at once, because a launcher can throw the first two away:

- in the log the process writes;
- in a message box, on Windows;
- in `PASSWORD-ONCE.txt` in the state directory, which deletes itself at your
  first successful login.

Then open **http://127.0.0.1:5823** and sign in as `admin`.

Lost it? `kubetower --reset-password` draws another. Nothing can give the old one
back.
