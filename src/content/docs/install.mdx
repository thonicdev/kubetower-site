## Download

Nothing is published yet. When the first version is tagged, a release carries
five builds — `windows/amd64`, `darwin/arm64`, `darwin/amd64`, `linux/amd64`,
`linux/arm64` — each archived with the licence beside the binary, and a
`SHA256SUMS` alongside.

<CommandRow command={null} placeholder="Available at v0" />

**Check the checksum before you run it.** A console holds the credentials to
every cluster you can reach, which makes it worth thirty seconds:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```

Until then, build it — the commands are on [Getting started](/docs).

## Let it install itself

The binary puts itself where the machine keeps applications, and takes itself
back out:

```bash
kubetower --install      # copies itself into place, adds a launcher
kubetower --uninstall    # removes both
```

It is a flag rather than a separate installer on purpose: the file you downloaded
is the file that installs, so there is no second binary to keep in version step,
and the checksum you checked covers both.

## Flags

| Flag | What it does |
| --- | --- |
| `--app` | Opens in its own window: a native frame on Windows, otherwise the browser you already have, without tabs or address bar |
| `--no-window` | Starts the server only, opens nothing |
| `--install` | Installs the binary and a launcher for this machine |
| `--uninstall` | Removes what `--install` put down |
| `--reset-password` | Draws a new password and prints it once |
| `--unattended` | No prompts and no window — for a service manager or a script |
| `--version` | The version, and the revision it was built from |
| `--help` | The same list, from the binary itself |

## What it writes to your disk

One directory, and you choose it with `KT_STATE_DIR` — `~/.kubetower` by default.
It holds your rail arrangement, your table layouts, the credentials file and the
archive.

Everything in it is disposable **except `credentials.json`**, which holds the
drawn password's hash and the session signing key. Delete it and the next start
draws a new password.

**It never writes to your kubeconfig.** It reads it where it already lives.

## Uninstall

```bash
kubetower --uninstall
rm -rf ~/.kubetower        # or whatever KT_STATE_DIR points at
```

Nothing else is left behind: no service, no daemon, no system-wide configuration,
and nothing changed in your kubeconfig.
