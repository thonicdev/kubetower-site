## First, read the log

Every start prints a short report: paths, tools found (`kubectl`, `helm`,
`aws`), settings in use. It is also saved in `~/.kubetower/kubetower.log`
(`/var/lib/kubetower/kubetower.log` in a container). Attach the log file to any
bug report: it contains no secrets.

## A cluster does not answer

Open the **Health** page. It tells you what failed and who can fix it:

| Message | Fix |
| --- | --- |
| does not resolve | A VPN that is not up, or a private DNS zone |
| SSO session | Your login expired, or the cluster does not know your identity. Sign in again on your machine (e.g. `aws sso login`) |
| IAM refused | A permission is missing on the cloud side. Ask your cloud administrator |
| refused | A local cluster seen from a container: see [Run in a container](/docs/container) |
| no answer | A VPN, a firewall, or the cluster is down |

## All EKS clusters went red at once

Your AWS SSO session expired. Run `aws sso login`.

In a container, mount `~/.aws` read-write.

## I lost my password

```bash
kubetower --reset-password
```

This creates a new password, shows it once, and signs everyone out once you
restart kubetower (unless you set `KT_SESSION_SECRET`). It does nothing if you set `KT_PASSWORD_HASH`: change the
hash instead.

## Nothing appears when I start it

Read `~/.kubetower/kubetower.log`. It says whether a window was opened, and why
not.

## The page does not load from Docker

Check that you published the port with `-p 127.0.0.1:5823:5823`.

## A port-forward opens but does not connect

In a container, publish the range and set it:

```bash
-p 127.0.0.1:30000-30031:30000-30031 -e KT_FORWARD_PORTS=30000-30031
```

## My Compose password never works

Double every `$` in the hash. This must print 60:

```bash
docker compose exec kubetower sh -c 'echo ${#KT_PASSWORD_HASH}'
```

## A list is empty and should not be

That is a bug: kubetower shows an error when it cannot read a list, never an
empty table. Please report it.

## Report a problem

Open an issue on [GitHub](https://github.com/thonicdev/kubetower/issues) with
the version (`kubetower --version`), how you ran it, and the start-up report.
